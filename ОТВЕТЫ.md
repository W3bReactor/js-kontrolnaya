## Часть A. Почему так

### A1 — почему изменилось и у `a`
Во второй строке написано: const b = a, у объектов копируются ссылки, а не само значение,
соответственно при изменении уже примитива в объекте b, будет изменен и объект a, так как они ссылаются
на один и тот же объект.


### A2 — почему `3` раньше `2`E
В js есть Event Loop, он решает порядок выполнения кода:
Сначала выводится синхронный код: 1, 4
Затем идут микротаски - промис: вывод 3
И только потом идет уже макротаска: вывод 2

### A3 — почему счётчик остался нулём
Проблема в том, что функция add - стрелочная и из-за этого у него нет собственного this и он берет this
внешнего объекта - ну тут он может быть либо window, либо module.exports - пустой объект

## Часть B. Что было не так

Четыре находки. По каждой: в чём была проблема и что вы исправили.

### Ошибка 1

**Было не так:**
/* ---------- сортировка по важности ---------- */

sortBtn.addEventListener("click", function () {
    tasks.sort();
    render();
});

sort() - по умолчанию сортирует объекты как строки "[object Object]",
поэтому при нажатии "Сортировать по важности" ничего не происходило
**Исправил:**
Нужно добавить comparator, который будет выдавать числа, подходящие под наш признак (важность),
т.е здесь нужно b.priority - a.priority 
если второй элемент - первый элемент < 0 свапаем

/* ---------- сортировка по важности ---------- */

sortBtn.addEventListener("click", function () {
tasks.sort((a, b) => b.priority - a.priority );
render();
});


### Ошибка 2

**Было не так:**
/* ---------- фильтр: только важные ---------- */

filterBtn.addEventListener("click", function () {
tasks.filter((task) => task.priority >= 5);
render();
});

filter - возвращает новый массив отфильтрованный, но здесь мы с ним ничего не делаем,
из-за чего при нажатии на кнопку "Только важные" ничего не происходило

**Исправил:**
Нужно переприсвоить tasks новый объект, чтобы он изменился
/* ---------- фильтр: только важные ---------- */

filterBtn.addEventListener("click", function () {
tasks = tasks.filter((task) => task.priority >= 5);
render();
});


### Ошибка 3

**Было не так:**
На каждое нажатие кнопки создавалась новая функция со своим лексическим
окружением, из-за чего всегда counter = 1
/* ---------- счётчик нажатий ---------- */

document.querySelectorAll(".btn").forEach((btn) => {
    btn.addEventListener("click", function () {
        const countActions = createCounter();
        actionsEl.textContent = countActions();
    });

**Исправил:**
Теперь countActions создается единожды и имеет одно и то же лексическое 
окружение
/* ---------- счётчик нажатий ---------- */
const countActions = createCounter();

document.querySelectorAll(".btn").forEach((btn) => {
    btn.addEventListener("click", function () {
    actionsEl.textContent = countActions();
    });
});


### Ошибка 4

**Было не так:**
item.dataset.id (параметр id) - возвращает строку, поэтому сравнение дает undefined и indexof даст -1
tasks.splice(-1, 1) удаляет последний элемент

/* ---------- удаление ---------- */

function removeTask(id) {
    const task = tasks.find((t) => t.id === id);
    tasks.splice(tasks.indexOf(task), 1);
    
    
    render();

**Исправил:**

## Часть C. Обоснуйте выбор

### C1 — какой вариант карточки и почему

**Выбираю:**
Выберу
<a class="card" href="item.html?id=7">Название</a>
 **Причины:**
1) доступность - скринридеры объявят тег a как ссылку
2) семантика - для SEO лучше иметь ссылку, чтобы робот смог её прочитать (к примеру, увидеть что вы ссылаетесь на какие-то классные статьи или просто увидеть контакты ваши)
3) удобность - можно открывать через таб ссылку или через ctrl + клик

### C2 — какой вариант вывода списка и почему

**Выбираю:**

users.forEach((u) => {
    const li = document.createElement("li");
    li.textContent = u.name;
    list.append(li);
});
**Причины:**
1) innerHTML - позволит сделать атаку на сайт, так как он принимает буквально HTML, поэтому
можно выполнить скрипт, который сделает зло.
2) Пользователь сам может ошибиться и написать < >, соответственно это корректно отображаться не будет
3) Неудобство работы с элементами в js - чтобы добавить какой-либо обработчик нужно будет писать прям в сам элемент, что не очень удобно, особенно, если огромная функция
